---
title: OAuth providers
---

GitHub, GitLab, and Google are each offered only when both halves of their credential are set. Each one closes sign-up exactly when `AUTH_ENABLE_SIGNUP` does: with registration off, a provider signs in an account that already exists and never creates one.

## GitHub

The login page offers a GitHub button only when both halves of the credential are set:

```bash
GITHUB_CLIENT_ID=…
GITHUB_CLIENT_SECRET=…
```

## Create the OAuth app

1. On GitHub, open **Settings → Developer settings → OAuth Apps → New OAuth App**.
2. Set the homepage URL to your deployment's origin (for local development, `http://localhost:3000`).
3. Set the authorization callback URL to `<origin>/api/auth/callback/github`.
4. Copy the client ID and generate a client secret, then set both environment variables.

## Callback URLs and the site URL

The auth module auto-detects the base URL from the incoming request. Set `NUXT_PUBLIC_SITE_URL` only for a custom domain or when you need deterministic OAuth callbacks:

```bash
NUXT_PUBLIC_SITE_URL=https://code-zero.example.com
```

## GitLab and Google

```bash
GITLAB_CLIENT_ID=…
GITLAB_CLIENT_SECRET=…
# A self-managed instance; leave empty for gitlab.com.
GITLAB_ISSUER=https://gitlab.example.com

GOOGLE_CLIENT_ID=…
GOOGLE_CLIENT_SECRET=…
```

Register the callback URLs `<origin>/api/auth/callback/gitlab` and `<origin>/api/auth/callback/google` with the provider.

Credentials are read when the server starts, and the sign-in page learns which providers exist from `/api/capabilities`, so adding or removing one needs a restart, not a rebuild.
